Gradle多项目构建

# Gradle 多项目构建

多项目构建（Multi-project Build）是 Gradle 的强项。与 Maven 的父子 POM 继承不同，Gradle 通过 settings.gradle 的 include 声明子项目，结构更扁平、更灵活。

# Maven 多模块 vs Gradle 多项目

对比项 Maven Gradle
组织方式 父子 POM 继承 settings.gradle + include
公共配置 父 POM <dependencies> / <dependencyManagement> 根 build.gradle 的 subprojects {}
模块间依赖 <dependency> + <type>pom</type> project(':module')
构建顺序 Reactor 自动排序 Task 依赖图自动排序
灵活性 低，固定继承链 高，可按需配置

# 项目结构

# 典型多项目结构

my-project/
├── settings.gradle           # 声明所有子项目
├── build.gradle              # 根项目构建脚本（公共配置）
├── gradle.properties         # 全局属性
├── gradle/
│   └── libs.versions.toml    # 统一版本管理
├── app/                      # 子项目：应用主模块
│   ├── build.gradle
│   └── src/
├── common/                   # 子项目：公共模块
│   ├── build.gradle
│   └── src/
└── shared/                   # 子项目：共享模块
    ├── build.gradle
    └── src/

# include 路径规则

include 的参数是项目路径，用冒号 : 分隔，对应目录层级：

// 平级子项目
include('app', 'common', 'shared')
// 对应目录：app/、common/、shared/

// 嵌套子项目
include('app:web', 'app:core')
// 对应目录：app/web/、app/core/

// 混合
include('app', 'app:web', 'app:core', 'shared')

# 自定义项目路径

默认情况下，include('app') 对应 app/ 目录。如果目录名和项目名不一致，可以用 project() 自定义：

include('app')
project(':app').projectDir = file('my-application-dir')

# 根 build.gradle 配置

根项目的 build.gradle 用于配置所有子项目的公共设置。

# subprojects 块

subprojects {} 对所有子项目应用配置：

// 根 build.gradle
subprojects {
    // 应用 Java 插件
    apply plugin: 'java'

    // 统一 group 和 version
    group = 'com.example'
    version = '1.0.0'

    // 统一仓库
    repositories {
        mavenCentral()
    }

    // 统一 JDK 版本
    java {
        toolchain {
            languageVersion = JavaLanguageVersion.of(21)
        }
    }

    // 统一编码
    tasks.withType(JavaCompile).configureEach {
        options.encoding = 'UTF-8'
    }
}

# subprojects vs allprojects

块 作用范围
allprojects {} 根项目 + 所有子项目
subprojects {} 仅所有子项目（不含根项目）

通常 repositories 放在 allprojects，插件和依赖配置放在 subprojects。

每个子项目有自己的 build.gradle，可以声明项目特有的配置。

# implementation project vs api project

dependencies {

    implementation project(':common')

    // common 的 API 暴露给 app 的下游
    api project(':common')

# convention plugin（约定插件）

对于复杂的多项目结构，推荐使用 convention plugin（约定插件）来封装公共配置，而不是在根 build.gradle 中用 subprojects {}。

JavaConventionPlugin.groovy：

package com.example

import org.gradle.api.Plugin
import org.gradle.api.Project

class JavaConventionPlugin implements Plugin<Project> {
    void apply(Project project) {
        project.with {
            apply plugin: 'java'

            java {
                toolchain {
                    languageVersion = JavaLanguageVersion.of(21)
                }
            }

            tasks.withType(JavaCompile).configureEach {
                options.encoding = 'UTF-8'
            }
        }
    }
}

# 构建顺序

Gradle 根据 Task 依赖关系自动确定构建顺序：

app 依赖 common
→ 构建 common（compileJava → jar）
→ 构建 app（compileJava → jar，classpath 中包含 common 的 jar）

# 多项目构建命令

命令 说明
gradlew build 构建所有子项目
gradlew :app:build 只构建 app 子项目
gradlew :app:bootRun 运行 app 子项目
gradlew :common:test 只测试 common 子项目
gradlew :app:dependencies 查看 app 的依赖树
gradlew projects 列出所有项目
gradlew build --parallel 并行构建所有子项目

# 只构建变更的模块

Gradle 的增量构建会自动跳过未变更的 Task。配合 --configure-on-demand 可以只配置参与构建的模块：

gradlew :app:build --configure-on-demand

# Maven 迁移注意事项

从 Maven 多模块迁移到 Gradle 多项目时，注意以下几点：

Maven 概念 Gradle 对应 注意事项
父 POM 根 build.gradle + subprojects {} 不需要父 POM 打包类型为 pom
<modules> include() 在 settings.gradle 中声明
<parent> 继承 subprojects {} 或 convention plugin Gradle 无显式继承概念
<dependencyManagement> Version Catalog 用 TOML 文件管理
模块间 <dependency> project(':module') 用项目路径引用
Reactor 构建顺序 Task 依赖图 自动排序，无需手动指定

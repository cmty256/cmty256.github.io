# Gradle 进阶与实战

本文涵盖 Gradle 的进阶用法：自定义 Task、镜像加速、属性配置、构建缓存、Maven 迁移等实战内容，并结合 interview-guide 项目的真实代码讲解。

# 自定义 Task

# Task 的基本定义

// 方式一：register（推荐，延迟创建）
tasks.register('myTask') {
    group = 'custom'
    description = '自定义任务示例'
    doLast {
        println '执行自定义任务'
    }
}

// 方式二：create（旧式，立即创建）
task myTask {
    doLast {
        println '执行自定义任务'
    }
}

# 自定义 Test Task

interview-guide 项目注册了专门的测试 Task，只运行特定标签的测试：

tasks.register('ragEvaluation', Test) {
    description = '运行 RAG 测评（需要 RUN_RAG_EVAL=true）'
    group = 'verification'
    testClassesDirs = sourceSets.test.output.classesDirs
    classpath = sourceSets.test.runtimeClasspath
    useJUnitPlatform {
        includeTags 'rag-eval'
    }
    jvmArgs '--enable-native-access=ALL-UNNAMED'
    systemProperty 'ragEval.reportDir', layout.buildDirectory.dir('reports/rag-eval').get().asFile.absolutePath
    outputs.upToDateWhen { false }
}

关键配置说明：

配置项 说明
testClassesDirs 测试类输出目录（复用主 test 的编译产物）
classpath 测试运行 classpath
useJUnitPlatform { includeTags } 只运行带指定标签的测试
systemProperty 传入系统属性
outputs.upToDateWhen { false } 禁用增量检查，每次都执行

这个 Task 复用了 sourceSets.test 的编译产物，不需要重新编译测试代码，只是用不同的标签过滤来运行不同的测试子集。

# Task 依赖

tasks.register('taskA') {
    doLast { println 'A' }
}

tasks.register('taskB') {
    dependsOn 'taskA'           // taskB 执行前先执行 taskA
    doLast { println 'B' }
}

// 执行 gradlew taskB 会先执行 taskA

# Task 输入输出

声明 Task 的输入输出，Gradle 可以据此做增量构建：

tasks.register('processData') {
    // 声明输入
    inputs.file('src/main/data/input.txt')
    // 声明输出
    outputs.file('build/data/output.txt')

    doLast {
        def input = file('src/main/data/input.txt').text
        file('build/data/output.txt').text = input.toUpperCase()
    }
}

# 从 .env 文件加载环境变量

interview-guide 项目在多个 Task 中读取 .env 文件注入环境变量：

tasks.register('ragEvaluation', Test) {
    // ...
    def envFile = rootProject.file('.env')
    if (envFile.exists()) {
        envFile.eachLine { line ->
            def trimmed = line.trim()
            if (trimmed && !trimmed.startsWith('#') && trimmed.contains('=')) {
                def (key, value) = trimmed.split('=', 2)
                if (System.getenv(key) == null) {
                    environment key, value
                }
            }
        }
    }
}

# 镜像加速配置

国内使用 Gradle 最大的痛点是下载慢。需要配置三个层面的镜像：

# 1. Gradle 发行版镜像

在 gradle/wrapper/gradle-wrapper.properties 中配置：

# 腾讯云（首选）
distributionUrl=https\://mirrors.cloud.tencent.com/gradle/gradle-9.6.1-bin.zip

# 阿里云（备选）
#distributionUrl=https\://mirrors.aliyun.com/gradle/gradle-9.6.1-bin.zip

# 增量构建

Gradle 的增量构建是自动的：每个 Task 声明了输入和输出，如果输入没变且输出已存在，Task 会被标记为 UP-TO-DATE 并跳过。

# 第一次构建
gradlew build
# > Task :compileJava
# > Task :test

# 第二次构建（无变更）
gradlew build
# > Task :compileJava UP-TO-DATE
# > Task :test UP-TO-DATE

# init 脚本

Gradle 支持在 ~/.gradle/init.d/ 或 ~/.gradle/init.gradle 中放置初始化脚本，对所有项目生效。

# 全局镜像配置

~/.gradle/init.gradle：

allprojects {
    repositories {
        def aliyunRepos = 'https://maven.aliyun.com/repository/public/'
        def aliyunPlugin = 'https://maven.aliyun.com/repository/gradle-plugin/'
        all { ArtifactRepository repo ->
            if (repo instanceof MavenArtifactRepository) {
                def url = repo.url.toString()
                if (url.startsWith('https://repo1.maven.org/maven2') || url.startsWith('https://jcenter.bintray.com')) {
                    repo.url = aliyunRepos
                }
                if (url.startsWith('https://plugins.gradle.org/m2')) {
                    repo.url = aliyunPlugin
                }
            }
        }
        maven { url = uri(aliyunRepos) }
        maven { url = uri(aliyunPlugin) }
    }
}

# Maven 迁移到 Gradle

# 自动迁移

Gradle 提供了从 Maven 自动迁移的命令：

# 在 Maven 项目根目录执行
gradle init
1
2

Gradle 会分析 pom.xml，自动生成 build.gradle、settings.gradle 和 libs.versions.toml。

自动迁移能处理大部分依赖和插件，但自定义插件配置、Profile 等需要手动调整。

# 手动迁移对照表

Maven 配置 Gradle 配置
<groupId> group = '...'
<artifactId> 项目名（settings.gradle 中定义）
<version> version = '...'
<packaging>jar</packaging> id 'java' 插件
<packaging>war</packaging> id 'war' 插件
<properties> ext { } 或 gradle.properties
<dependencies> dependencies { }
<dependencyManagement> Version Catalog 或 platform()
<build><plugins> plugins { }
<profiles> if (project.hasProperty('xxx')) 或 SourceSet
<modules> include()
父 POM 继承 subprojects {} 或 convention plugin

# scope 迁移对照

Maven scope Gradle 配置项
compile implementation（或 api）
provided compileOnly
runtime runtimeOnly
test testImplementation
import（BOM） platform()

# Profile 迁移

Maven 的 Profile 在 Gradle 中用条件逻辑替代：

// Maven Profile → Gradle 条件配置
def profile = project.findProperty('env') ?: 'dev'

if (profile == 'prod') {
    dependencies {
        implementation 'org.springframework.boot:spring-boot-starter-actuator'
    }
    tasks.named('bootRun') {
        systemProperty 'spring.profiles.active', 'prod'
    }
} else {
    dependencies {
        implementation 'org.springframework.boot:spring-boot-devtools'
    }
}

# 常见问题

# 1. 依赖下载失败

现象：Could not resolve xxx

解决：

  1. 检查 repositories 是否配置了正确的镜像
  2. 尝试 gradlew build --refresh-dependencies 强制刷新
  3. 检查网络连接和代理配置

# 2. Lombok 不生效

现象：编译报错找不到 getter/setter 方法

解决：确保同时配置 compileOnly 和 annotationProcessor：

dependencies {
    compileOnly libs.lombok
    annotationProcessor libs.lombok
}
1
2
3
4

# 3. MapStruct + Lombok 冲突

现象：MapStruct 生成的代码找不到 Lombok 生成的方法

解决：确保 Lombok 在 MapStruct 之前配置，并添加 binding：

dependencies {
    compileOnly libs.lombok
    annotationProcessor libs.lombok

    implementation "org.mapstruct:mapstruct:${libs.versions.mapstruct.get()}"
    annotationProcessor "org.mapstruct:mapstruct-processor:${libs.versions.mapstruct.get()}"
    annotationProcessor 'org.projectlombok:lombok-mapstruct-binding:0.2.0'
}

# 4. 构建慢

解决：

  1. 启用 Daemon、并行、缓存：gradle.properties 配置
  2. 使用 --configure-on-demand
  3. 检查是否有耗时操作在配置阶段执行（应移到 doLast）
  4. 使用 --profile 分析构建耗时

# 5. 版本冲突

现象：Conflict found for ...

解决：

// 查看依赖树定位冲突
gradlew dependencies --configuration runtimeClasspath

// 强制指定版本
configurations.all {
    resolutionStrategy {
        force 'org.slf4j:slf4j-api:2.0.9'
    }
}

# interview-guide 项目配置总结

interview-guide 项目的 Gradle 配置涵盖了本文大部分内容：

配置文件 作用
settings.gradle 插件仓库镜像、工具链插件、项目名称、子项目声明
gradle.properties JDK 路径、JVM 编码参数
gradle/libs.versions.toml Version Catalog，集中管理所有依赖版本
gradle/wrapper/gradle-wrapper.properties Gradle 发行版镜像（腾讯云）
app/build.gradle 插件、依赖、Toolchain、编码、自定义 Task、bootRun 配置

关键配置亮点：

  1. 镜像加速：腾讯云（Gradle 发行版）+ 阿里云（依赖和插件）
  2. Version Catalog：所有版本集中在 libs.versions.toml
  3. Toolchain：自动使用 Java 25
  4. 自定义 Task：ragEvaluation、voiceContextEvaluation 按标签运行不同测试
  5. .env 注入：bootRun 和测试 Task 自动加载 .env 文件
  6. 编码配置：全局 UTF-8，避免中文乱码

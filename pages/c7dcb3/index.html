# .gitignore 最佳实践

# 什么是 .gitignore？

.gitignore 是一个文本文件，告诉 Git 哪些文件或目录不应该被跟踪（不纳入版本控制）。

应该忽略的文件类型：

  • 构建产物：dist/、target/、build/、*.class
  • 依赖目录：node_modules/、.mvn/
  • IDE 配置：.idea/、.vscode/、*.iml
  • 环境变量文件：.env.local、.env.*.local（含敏感信息）
  • 系统文件：.DS_Store、Thumbs.db
  • 日志文件：*.log、logs/
  • 缓存目录：.vite/、.cache/

不应该忽略的文件：

  • 源代码
  • 配置文件模板（如 .env.example、.env.development）
  • 文档（README、DESIGN 等）
  • 依赖锁定文件（pnpm-lock.yaml、package-lock.json、pom.xml）

# .gitignore 语法规则

语法 含义 示例
# 注释 # 这是注释
*.log 匹配所有 .log 文件 error.log、app.log
node_modules/ 匹配名为 node_modules 的目录（任意层级） src/node_modules/、node_modules/
/dist 只匹配根目录下的 dist dist/（不匹配 src/dist/）
dist/ 匹配任意层级的 dist 目录 dist/、src/dist/
!file 取反，强制跟踪（即使前面被忽略） !lib/import.js
**/logs 匹配任意层级的 logs 目录 logs/、a/b/logs/
temp/*.txt 匹配 temp 目录下的 .txt 文件 temp/test.txt

注意：! 取反规则不能重新包含已经被上级目录忽略的文件。例如 node_modules/ 已忽略，!node_modules/lib.js 无效。

# 常见问题与陷阱

# 1. .gitignore 不生效？

原因：文件已经被 Git 跟踪了，.gitignore 只对未跟踪的文件生效。

解决：先从 Git 索引中移除（不删除本地文件），再提交：

# 移除单个文件
git rm --cached <file>

# 移除整个目录
git rm -r --cached <directory>

# 提交
git commit -m "chore: 移除不应跟踪的文件，添加 .gitignore"

# 2. 已经提交了 .env 等敏感文件怎么办？

# 1. 从历史记录中彻底移除（谨慎操作）
git filter-branch --force --index-filter \
  'git rm --cached --ignore-unmatch .env' \
  --prune-empty --tag-name-filter cat -- --all

# 2. 添加到 .gitignore
echo ".env" >> .gitignore

# 3. 强制推送
git push --force --all

# 4. ⚠️ 立即更换所有泄露的密钥/密码！

# 3. 全局 .gitignore

可以为所有项目设置一个全局 .gitignore，忽略系统文件和 IDE 文件：

# 创建全局 .gitignore 文件
echo ".DS_Store
.idea/
.vscode/
*.iml
Thumbs.db" > ~/.gitignore_global

# 配置 Git 使用全局 .gitignore
git config --global core.excludesfile ~/.gitignore_global

# .gitignore 编写建议

  1. 早建早好：项目初始化时就创建 .gitignore，避免后续清理麻烦
  2. 宁多勿少：不确定是否该跟踪的文件，先忽略。需要跟踪时用 ! 取反
  3. 按技术栈选择：参考 github/gitignore (opens new window) 官方模板
  4. 团队统一：.gitignore 提交到仓库，团队成员共享同一份配置
  5. 不要忽略锁定文件：pnpm-lock.yaml、package-lock.json、pom.xml 等依赖锁定文件必须提交，保证团队依赖版本一致
